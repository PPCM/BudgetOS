# Changelog - 2026-05-02

## Summary
Applied the same two-step deactivate-then-permanent-delete flow to user accounts (mirroring what was done for bank accounts). Also fixed a hidden side-effect in the group "remove member" action which used to hard-delete the user from the system.

## Changes

- [src/models/User.js] User.delete() now refuses an active user (throws BadRequestError USER_MUST_BE_SUSPENDED). The caller must suspend first
- [src/controllers/groupController.js] removeMember now only removes the group_members link; previously it also called User.delete() which silently destroyed the user account and all of their data. Self-removal now returns CANNOT_REMOVE_SELF (was CANNOT_DELETE_SELF)
- [client/src/pages/AdminUsers.jsx] Replaced the always-visible Delete button with state-driven actions: active users show Edit + Suspend (window.confirm). Suspended users show Reactivate + Permanent Delete (typed-email confirmation modal listing every cascade target before enabling the red button)
- [client/src/locales/{fr,en,de,es,it,pt,ru,sv,zh}.json] Added admin.users.suspend/reactivate/permanentDelete + warning modal copy. Rewrote admin.groups.confirmDeleteMember to reflect the new (correct) semantic: "remove from group, account preserved"
- [tests/integration/admin.test.js] Reworked delete-user tests to suspend before deleting + added two new tests: refuse-active-user (returns USER_MUST_BE_SUSPENDED) and cascade-on-permanent-delete (verifies accounts are wiped)
- [tests/integration/groups.test.js] Replaced "should delete a user when removing a member" with "removes only the membership and keeps the user account". Renamed the self-removal test for the new error code
- [client/src/components/ConfirmModal.jsx] New reusable confirmation modal (warning/success/default variants) so reversible lifecycle actions (suspend/deactivate/reactivate, remove-from-group) share the visual style of the typed-name permanent-delete modals
- [client/src/pages/Accounts.jsx] Replaced window.confirm for deactivate/reactivate with ConfirmModal (warning/success variants)
- [client/src/pages/AdminUsers.jsx] Replaced window.confirm for suspend/reactivate with ConfirmModal
- [client/src/pages/AdminGroups.jsx] Replaced window.confirm for remove-member with ConfirmModal; renamed the action from "Delete" to "Remove from group" with a UserMinus icon and updated success toast/title accordingly
- [client/src/locales/{fr,en,de,es,it,pt,ru,sv,zh}.json] Added admin.groups.removeMember; rewrote confirmDeleteMember to interpolate the user's email; reworded memberDeleted to "removed from group"
- [client/src/components/ConfirmModal.jsx] Added "danger" variant (red, Trash2 icon) for destructive actions
- [client/src/pages/{Categories,CreditCards,Payees,PlannedTransactions,Transactions,AdminGroups,AdminSettings}.jsx] Replaced every remaining window.confirm() (7 sites) with the shared ConfirmModal so all destructive prompts have the same look. Native browser confirm dialogs are now gone from the app entirely.

## CI / Docker image hardening (releases v1.6.1 → v1.6.6)

- [.github/workflows/docker-publish.yml] Resolve target ref dynamically (release event vs schedule/dispatch); add `pull: true` so the FROM image is always fetched fresh (defeats GHA cache); add weekly schedule (Mon 04:00 UTC) and `workflow_dispatch`; bumped every Docker action to its current major (qemu/buildx/login v3→v4, metadata v5→v6, build-push v6→v7, dockerhub-description v4→v5) and `actions/checkout` v4→v5 — silences the Node.js 20 deprecation annotation
- [.github/dependabot.yml] New file. Tracks `/docker` (Dockerfile) and `/` (GitHub Actions) on a weekly cadence; ignores Node major bumps so we stay on the LTS line
- [docker/Dockerfile] Pinned base from floating `node:24-alpine` to immutable `node:24.15.0-alpine3.23`. Added `org.opencontainers.image.base.name` label so license/image scanners can identify the base. Added a build step that rewrites `node_modules/jszip/package.json` to declare MIT only (jszip is dual MIT / GPL-3.0-or-later) and trims the bundled LICENSE.markdown to its MIT section so SBOM and file-based scanners agree
- [package.json, client/package.json] Replaced the incorrect `"license": "MIT"` claim with `"SEE LICENSE IN LICENSE"` (project actually ships under PolyForm Noncommercial 1.0.0)

## Notes
- removeMember side-effect was the most dangerous bit - clicking the trash icon next to a member in the AdminGroups page silently nuked their entire profile (accounts, transactions, recurring, every group membership). Now it only severs the membership row
- Permanent user delete still cascades through ON DELETE CASCADE FKs on every table that references users.id, so the destructive intent is preserved when explicitly invoked from the Users page
- Docker Scout grade reached B (license fix landed). The "Up-to-Date Base Images" policy remained "No data / Never" despite all documented mitigations (provenance attestations, immutable patch tag, OCI base.name label, pull true). Likely a Scout-side limitation around SLSA v1 / multi-arch handling. See `memory/docker-scout.md` for the investigation summary
